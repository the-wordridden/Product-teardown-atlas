**A link opens a live file, and anyone with the link is in it.** The moment it clicks, by Intercom's account, is opening a colleague's file and realising there's nothing to download, version or send: "the absence of files" <Evidence id="migration.intercom.2019" />.

## The objects

Everything lives in a **file**; inside it, the unit is a **frame**, a nestable container that auto layout, constraints and prototyping all work on <Evidence id="docs.frames" />. A **component** is a frame you've promised to reuse: every **instance** is a linked copy that picks up changes to the main <Evidence id="docs.components" />. Publish components to a **team library** and every file in the team can use them. That's the whole design system story.

## Under the hood, as of 2019

Evan Wallace's 2019 write-up is precise where most coverage is vague <Evidence id="architecture.multiplayer.2019" />. Figma rejected operational transforms as "unnecessarily complex for our problem space", and it does **not** use true CRDTs. The server is the single authority, so a simpler custom system borrows CRDT ideas: one process per document, WebSocket sync, client-generated IDs, offline edits replayed on reconnect.

He also listed what it can't do:

- two people can't edit the same text value at once
- conflicting property changes resolve last write wins
- simultaneous moves between parents can make objects vanish briefly ("not great," in his words)

Nothing I found describes the current architecture, so whether those limits still hold is open, and it has competitive weight.
